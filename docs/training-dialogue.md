# 训练信息补充问答流程

更新日期：2026-09-05。用户已明确选择 Agent 主导的逐轮问答；这是交互偏好，动作记录规则仍以 `AGENTS.md` 为准。

## 开始前

- 先分辨用户是在记录新完成的训练、补充已有记录，还是仅讨论流程。讨论流程不产生训练事实。
- 读取本轮描述、相关记录与 profile。将信息分成已报告事实、已确认默认偏好、仍需确认的缺口。不能把历史重量、次数、休息或质量评价自动复用到本次。
- 每轮只问一个清楚、具体的问题；允许用户在回答中一次补充多个信息，后续不机械重复预设问题。

## 提问优先级

下面是按需选择的顺序，不是每次必须问完的问卷。

1. **日期**：仅在无法从“今天/昨天/具体日期”和当前上下文确定时询问。补充历史记录而目标不明时，先问日期，随后定位动作记录。
2. **动作与先后**：未提供时询问第一个动作或实际动作顺序；明确按顺序描述时直接使用该顺序，不再确认。
3. **动作消歧**：先查词典和历史。只问区分候选所需的信息；自定义动作仍需确认主要训练部位及必要定义。
4. **每组数据**：例如“这个动作每组分别用了多少重量、做了几次？”它是同一组记录问题。自重动作询问次数，计时动作询问时长；已知部分只追问缺失部分。
5. **影响事实解释的缺口**：例如每侧还是合计重量、左右各组数据、热身与工作组的区别。只在原话有相关歧义时询问，不无故重新确认双侧或单位默认值。
6. **可选分析信息**：核心事实齐全后，优先询问与本次变化有关的动作质量，再视需要询问实际休息、执行设置或恢复备注。既有 RIR 偏好不重复询问；用户主动报告例外时按实际保存。

可选问题允许“不记得/没记录/跳过”。用户要求直接记录时，跳过可选问题；未知值省略，不把沉默视为质量保持、恢复良好或沿用上次休息。

## 示例（虚构对话，不写入训练日志）

用户：记录今天训练，第一个是杠铃平板卧推，90kg 两组。

Agent：这两组分别完成了几次？

用户：8 次和 7 次。

Agent：这次卧推的动作质量有什么变化？这项可以跳过。

用户：幅度比上次完整了，做得更稳。

Agent：还有其他动作需要记录吗？

用户：没有，直接记录。

Agent：已记录今天第 1 个动作：杠铃平板卧推，90kg × 8、7 次；按既有偏好，工作组 RIR 0。保留“幅度比上次完整了，做得更稳”的备注，未提供的休息信息未填入。记录已校验。

示例中的最后一句仅在脚本实际写入且校验通过后才能使用；不能把示例、预计训练或未完成问答说成已记录。

## 保存与边界

- 用户已经要求记录，且信息充分时直接保存并校验，不增加通用的最终批准步骤。
- 可选项尽量在当前动作首次写入前补充，避免为了问答产生不必要的历史重写。已有记录需补充时，先定位精确 ID、说明修改对象，并按既有纠错规则做最小变更；不重复追加相同动作。
- 某动作等待必要消歧时保留其原始位置；其他已明确的动作可按原有规则处理，不以问答结束时间重排顺序。
- 不要求用户提供 JSON、字段名、标准版本号或模板 ID。结构化标识由 Agent 根据用户确认的描述整理，不能反向把字段猜测当作用户事实。
- 问答结束回报实际保存内容及默认假设；没有完成保存时清楚说明待补项。记录训练并不自动授权 Git 提交或推送。
